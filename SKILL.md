# Webmatic Project Management

Use this skill when Webmatic needs to plan, track, review, prioritize, or manage one or more client projects.

The objective is to keep projects organized, profitable, on schedule, and protected from scope creep while maintaining professional client communication.

Never invent project information.

## 1. Project Information

When available, track:

- Project name
- Client
- Service
- Package
- Quoted price
- Start date
- Target completion date
- Current status
- Priority
- Scope
- Deliverables
- Client responsibilities
- Pending client items
- Current task
- Next action
- Blockers
- Payment status
- QA status
- Launch status
- Handover status
- Maintenance opportunity
- Risks
- Notes

Only use confirmed information.

## 2. Project Stages

Use:

1. New
2. Planning
3. Awaiting Client
4. In Development
5. Internal QA
6. Client Review
7. Revisions
8. Ready to Launch
9. Launched
10. Handover
11. Maintenance
12. On Hold
13. Completed
14. Cancelled

Choose the stage that accurately represents the current project state.

## 3. Priority

### Critical
Immediate impact on:

- Website availability
- Security
- Payments
- Production systems
- Major deadline
- Revenue-critical functionality

### High
Important work affecting:

- Delivery
- Client satisfaction
- Deadline
- Revenue
- Major functionality

### Normal
Standard planned project work.

### Low
Non-urgent improvements or optional work.

Do not classify everything as High or Critical.

## 4. Daily Project Review

When performing a daily review, identify:

1. Critical issues
2. High-priority tasks
3. Approaching deadlines
4. Pending client responses
5. Technical blockers
6. Tasks that can be completed today
7. Projects at risk
8. Revenue-impacting work
9. Next actions

Focus on practical actions rather than long summaries.

## 5. Weekly Project Review

Review:

### Delivery
- Completed projects
- Active projects
- Delayed projects
- Projects approaching launch

### Client
- Pending approvals
- Missing information
- Follow-ups
- Scope changes

### Technical
- Bugs
- Security issues
- Performance problems
- Hosting/DNS/email issues

### Financial
- Outstanding payments
- Additional work
- Scope expansion
- Profitability concerns

### Business Development
- Maintenance opportunities
- Upsells
- Recurring services
- Referrals

## 6. Deadline Management

Track:

- Agreed deadline
- Current progress
- Remaining deliverables
- Client dependencies
- Technical blockers
- Revision status
- Launch requirements

If a deadline is at risk, identify the actual reason.

Possible reasons:

- Webmatic workload
- Client delay
- Missing content
- Missing credentials
- Scope expansion
- Technical issue
- Third-party dependency
- Payment delay
- Approval delay

Do not hide deadline risks.

## 7. Client Dependencies

Track items Webmatic needs from the client:

- Logo
- Images
- Content
- Product information
- Hosting access
- Domain access
- DNS access
- Payment gateway information
- Business information
- Approvals
- Required documents

For each blocked dependency identify:

- Required item
- Why it is required
- Affected task
- What can continue without it
- Client action required

## 8. Blocker Management

For each meaningful blocker record:

### Problem
What is blocked.

### Cause
Known or suspected cause.

### Impact
What is affected.

### Owner
Who needs to act.

### Required Action
What needs to happen.

### Risk
What happens if it remains unresolved.

Do not treat symptoms as confirmed root causes.

## 9. Scope Management

Separate:

### Included
Approved project scope.

### Additional
Work outside the approved scope.

### Optional
Useful but non-essential improvements.

### Third-Party
External products/services/costs.

### Client Responsibility
Information or actions required from the client.

When scope expands:

1. Identify the new requirement.
2. Compare it with approved scope.
3. Determine additional effort.
4. Check profitability.
5. Prepare an additional quote when appropriate.
6. Get approval before substantial additional work.

## 10. Project Risk

Monitor:

- Scope creep
- Missing client content
- Delayed approvals
- Payment delays
- Technical complexity
- Third-party dependencies
- Unrealistic deadlines
- Security risks
- Hosting problems
- Integration failures
- Excessive revisions

Classify risk as:

- Low
- Medium
- High
- Critical

Do not invent risks without a reasonable basis.

## 11. Payment Tracking

Where information is available, track:

- Quoted amount
- Deposit
- Milestone payments
- Outstanding amount
- Final payment
- Payment status

Possible statuses:

- Pending
- Partially Paid
- Paid
- Overdue
- On Hold

Do not invent payment status.

Avoid substantial additional work when agreed payment conditions have not been met.

## 12. QA Management

Before client delivery or launch, verify where applicable:

### General
- Desktop
- Tablet
- Mobile
- Navigation
- Links
- Buttons
- Forms
- Images
- Typography
- Spacing

### WordPress
- Core
- Theme
- Plugins
- Elementor/WPBakery
- Forms
- Permalinks
- Cache
- Security

### WooCommerce
- Products
- Variations
- Cart
- Checkout
- Payment
- Shipping
- Emails
- Coupons

### Shopify
- Products
- Collections
- Cart
- Checkout
- Theme
- Apps
- Navigation
- Mobile

Never mark QA complete without appropriate verification.

## 13. Launch Management

Before launch:

- Confirm final approval
- Confirm required payment
- Confirm backup
- Confirm domain/DNS
- Confirm SSL
- Confirm forms
- Confirm integrations
- Confirm responsive behavior
- Confirm critical functionality

After launch:

- Test production site
- Test important forms
- Test e-commerce where applicable
- Check HTTPS
- Check critical pages
- Check important integrations
- Check analytics where applicable
- Monitor immediate errors
- Confirm launch with client

## 14. Handover

Handover may include:

- Website access
- Hosting information
- Domain information
- Basic instructions
- Maintenance information
- Third-party service information
- Technical notes
- Backup information

Never store passwords, API keys, payment credentials, or secrets directly in project notes.

Use secure credential management.

## 15. Maintenance Conversion

After project completion, identify genuine opportunities for:

- Website maintenance
- Security monitoring
- Backups
- Updates
- Performance optimization
- SEO
- Content updates
- Technical support
- Hosting management
- E-commerce management

Only recommend recurring services when they provide genuine value.

## 16. Project Completion

A project can be considered Completed when:

- Approved scope is delivered
- Required QA is completed
- Client approval is obtained
- Required payment conditions are satisfied
- Launch/handover is completed where applicable
- Critical outstanding issues are resolved or documented

After completion:

1. Confirm final status.
2. Confirm handover.
3. Identify maintenance opportunity.
4. Review profitability.
5. Record lessons learned.
6. Close remaining tasks.

## 17. Profitability Review

After major projects review:

- Quoted price
- Actual time
- Additional work
- Revision volume
- Technical complexity
- Third-party costs
- Client delays
- Unexpected issues
- Effective hourly return
- Overall profitability

Use findings to improve future estimation and scope control.

Do not automatically change official Webmatic pricing based on a single project.

## 18. Project Communication

When reporting project status, use:

### Current Status

### Completed

### Remaining

### Pending Client Items

### Blockers

### Risks

### Next Action

### Next Milestone

Avoid vague statements such as:

- Almost done
- Nearly finished
- Just a few things left
- Will finish soon

Use specific information whenever available.

## 19. Project Dashboard

When asked for an overall project review, use a table where useful:

| Project | Client | Status | Priority | Deadline | Blocker | Next Action |
|---|---|---|---|---|---|---|

Do not fabricate missing values.

## 20. Recommended Daily Prioritization

When multiple projects compete for attention, consider:

1. Critical production/security issues
2. Revenue-critical issues
3. Approaching committed deadlines
4. Blocked projects that can be unblocked quickly
5. High-value client deliverables
6. Tasks that unlock other work
7. Standard project tasks
8. Low-priority improvements

Consider business impact, urgency, dependencies, effort, and opportunity cost.

## 21. Important Rules

- Never invent project status.
- Never invent deadlines.
- Never invent payment status.
- Never invent client approvals.
- Never invent completed work.
- Protect approved scope.
- Detect scope creep early.
- Keep client dependencies visible.
- Protect project profitability.
- Identify risks before they become major problems.
- Never store credentials in project notes.
- Verify QA before launch.
- Document important changes.
- Recommend a specific next action.
- Use actual project information whenever available.
